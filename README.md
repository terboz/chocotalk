# chocotalk

chocotalk は、Cloudflare Workers + Durable Objects（SQLite）+ 静的アセットで動く、ビルド不要のグループチャットです。ホストがルームを作成し、ゲストは QR コードの URL からブラウザだけで参加できます。アカウント登録はありません。

フロントエンドは `public/` の静的ファイルのみで、ビルドコマンドはありません。ルームごとのデータは Durable Object の SQLite に保存されます。

## 主な機能

- **ルーム作成**: ホストは `/host` から複数のルームを作成できます。このブラウザで作成したルームはホスト用ホームに履歴として残ります（最大 50 件）。
- **ホームの使い分け**: `/` はゲスト用（ルームコードで参加）、`/host` はホスト用（ルーム作成・管理）です。
- **ルーム削除**: ホスト用ホームの各ルーム行から、ルームとメッセージ履歴を削除できます。
- **ゲスト参加**: QR コードの URL（`/r/<ルームコード>`）または 8 文字のルームコードで参加します。参加時にルームごとの表示名を設定します。
- **ホスト操作**: ルームの閉鎖、既読表示の ON/OFF、参加用 QR コードの表示、参加 URL のコピー。URL コピーは QR コードのダイアログ内にあります。
- **メッセージ**: テキスト、画像、絵文字スタンプ（20 種類）。
- **画像**: クライアント側で長辺 1280px を上限に JPEG 圧縮し、data URL 240,000 文字以下に収めます。元ファイルは 25MB までです。
- **既読表示**: ホストが ON にすると、自分の発言に既読人数が表示されます。新規ルームでは既定で ON です。OFF にすると現在の既読状態はクリアされ、ON に戻すと各参加者の現在位置から再表示されます。
- **再接続**: WebSocket が切れると指数バックオフで自動再接続します（最大 15 秒間隔）。
- **PWA / 通知**: PWA マニフェストと Service Worker があり、簡易通知に対応しています。詳細は「通知の仕組みと制約」を参照してください。
- **履歴**: ルームごとに直近 300 件を保存します。参加・再接続時に読み込むのは直近 200 件です。
- **画像の遅延取得**: 履歴表示時に、画像だけを個別 API から取得します。
- **閉鎖時の削除**: ルームを閉じると、メッセージと既読データ（画像を含む）を削除します。

## ファイル構成

```text
chatroom/
├─ .gitignore
├─ package.json
├─ wrangler.toml
├─ src/
│  └─ worker.js
└─ public/
   ├─ index.html
   ├─ app.js
   ├─ styles.css
   ├─ manifest.webmanifest
   ├─ sw.js
   ├─ icons/
   │  ├─ apple-touch-icon.png
   │  ├─ icon-192.png
   │  ├─ icon-512.png
   │  └─ icon.svg
   └─ vendor/
      └─ qrcode.js
```

- `src/worker.js`: Worker の API と、`Room` / `Directory` の Durable Object。
- `public/app.js`: 画面、WebSocket 接続、画像圧縮、通知、QR コードなどのクライアント処理。
- `public/sw.js`: 静的アセットのキャッシュと、通知クリック時の画面オープン。
- `wrangler.toml`: 静的アセット、Durable Object のバインディング、migration の設定。
- `node_modules/` と `.wrangler/` は生成物で、`.gitignore` の対象です。

## 使い方

### ホストとしてルームを作る

1. `/host` で「あなたの名前」と「ルーム名」を入力し、「ルームを作る」を押します。
2. ルーム画面のメニュー（☰）から「参加用QRコードを表示」を選び、QR コードまたは参加 URL を共有します。「URLをコピー」もこの画面から行えます。
3. 同じメニューの「ホスト設定」で、既読表示の ON/OFF とルームの閉鎖ができます。
4. ルームの閉鎖は取り消せません。閉鎖後は参加者全員がメッセージを送信できなくなります。

### ゲストとして参加する

1. 共有された QR コードを読み取るか、参加 URL を開きます。ゲスト用ホーム（`/`）でルームコードを入力して参加することもできます。
2. 表示名を入力して参加します。表示名はルームごとに設定され、参加後もメニューから変更できます。
3. アカウント登録やパスワードはありません。

## ローカル起動

### 必要条件

Node.js 22.21.0 以降（または 24 系）を推奨します。

> **注意（検証時に確認された不具合）**
> Node.js 22.12.0 では、日本語を含むパス（例: `C:\Users\...\デフォルトプロジェクト\chatroom`）で Node 自体が `0xC0000005` でクラッシュし、`wrangler` が起動しません。Node.js を 22.21.0 以降へ更新するか、`C:\work\chatroom` のような ASCII のみのパスへ移動してください。
>
> `package.json` の `engines` は `>=22.12.0` ですが、上記の理由から 22.12.0 は避けてください。

### 起動手順

```powershell
cd chatroom
npm install
npm run dev
```

`http://localhost:8787` を開きます。

ローカルデータは `chatroom/.wrangler/state` に保存されます。このディレクトリを削除すると、ローカルのルーム・メッセージなどはリセットされます。

> この環境では、Node.js 22.12.0 の不具合で `npm install` の postinstall が失敗したため、暫定回避として `npm install --ignore-scripts` で導入しました。Node.js を更新した後は、通常の `npm install` を推奨します。

### 同一 LAN のスマートフォンから開く

```powershell
npx wrangler dev --ip 0.0.0.0
```

1. Windows ファイアウォールで Node.js の受信（プライベートネットワーク）を許可します。
2. PC の LAN IP を使い、スマートフォンで `http://192.168.x.x:8787` を開きます。
3. PC 側も `http://192.168.x.x:8787` で開いてください。QR コードはアクセス中のオリジンから生成されるため、`localhost` で開くとスマートフォンから読めない URL の QR になります。

LAN IP の `http` では、Service Worker や通知が制限される場合があります。スマートフォン実機で通知まで試す場合は、デプロイ後の HTTPS URL を使用してください。

## デプロイ（Cloudflare 無料枠）

### 手順

1. Cloudflare アカウント（Free）を用意します。
2. Cloudflare にログインします。

   ```powershell
   npx wrangler login
   ```

3. デプロイします。

   ```powershell
   npm run deploy
   ```

初回デプロイ時に、`wrangler.toml` の migration（`v1`）が適用され、`Room` と `Directory` が SQLite の Durable Object として作成されます。

### 公開 URL

```text
https://chocotalk.<account-subdomain>.workers.dev
```

`wrangler.toml` の `name` は `chocotalk` です。変更すると公開 URL も変わります。独自ドメインは不要で、`workers.dev` は無料で利用できます。

QR コードはデプロイ後の URL から生成されるため、公開後はその URL を開いて QR コードを表示してください。

### 無料枠の目安

以下は執筆時点（2026 年 11 月）の目安です。最新の正確な条件は Cloudflare 公式の料金ページを確認してください。

| 項目 | 目安 |
| --- | --- |
| Workers / Durable Objects のリクエスト | 100,000 リクエスト / 日 |
| Durable Objects SQLite のストレージ | 5GB / アカウント |
| rows written | 100,000 / 日 |

小規模な友達内利用向けです。画像を多用する用途や、大規模な公開には向きません。

## データの保存と削除

- メッセージ、画像、既読情報は、ルームごとの Durable Object SQLite に保存されます。
- メッセージはルームごとに直近 300 件を保持します。ただし、参加・再接続時の `welcome` でクライアントに返すのは直近 200 件です。
- 画像はメッセージの data URL として保存され、履歴表示時に `/api/rooms/<ルームコード>/messages/<メッセージID>/media` から遅延取得されます。
- ルームを閉じると、`messages` と `reads` が削除されます。画像もメッセージと一緒に削除されます。
- ホスト用ホーム（`/host`）の「削除」からルームを削除できます。削除したルームとメッセージ履歴は復元できません。このブラウザの履歴（`localStorage`）からも削除されます。
- 閉鎖後もルームのメタデータ（ルーム名、コード、閉鎖状態など）は残ります。参加 URL を開くと閉鎖画面が表示されます。
- 無料枠を守るため、画像のクライアント圧縮（data URL 240,000 文字以下。サーバー側の上限は 250,000 文字）、履歴 300 件、閉鎖時の削除、画像の遅延取得、送信・既読・名前変更・API・ルーム作成の簡易レート制限を実装しています。

## セキュリティと制約

- アカウント登録はありません。ホスト判定は、ブラウザの `localStorage` に保存した `hostId` のみです。**ブラウザデータを消すとホスト権限を失います。** 別の端末・別のブラウザではホスト操作はできません。
- `hostId` は実質的なホスト鍵です。第三者に知られるとホスト操作が可能になります。本格的な認証ではありません。
- ルームコードは 8 文字のランダムな文字列です。推測は困難ですが、URL を知っている人は合言葉なしで参加できます。
- メッセージと画像は Cloudflare 上に保存されます。E2E 暗号化ではありません。
- ルームを閉じるとアプリの DB からメッセージと既読データを削除しますが、ルームのメタデータは残ります。
- ホーム画面のルーム履歴も `localStorage` に保存されます。ブラウザデータを消すと履歴も失われます。

## 通知の仕組みと制約

- Web Push ではなく、Service Worker + Notification API による簡易通知です。通知にはブラウザの許可が必要です。
- 新着メッセージを受信したとき、ページが非表示（別タブやバックグラウンド）の場合に通知します。自分のメッセージでは通知しません。
- ページを完全に閉じる、またはブラウザを終了すると WebSocket が切れるため、通知は届きません。Push 配信は未実装です。
- iOS で Web アプリの通知を使うには、iOS 16.4 以降で、Safari の「ホーム画面に追加」から開いた PWA である必要があります（Web Push の制約）。本アプリは Push を使わないため、この条件を満たしてもページを閉じた状態では通知されません。
- ローカル開発では `localhost` なら Service Worker と通知を利用できます。LAN IP の `http` では Service Worker が制限される場合があります。スマートフォン実機で通知まで確認する場合は、デプロイ後の HTTPS URL を使用してください。

## よくあるトラブル

| 症状 | 対処 |
| --- | --- |
| `wrangler` が無出力で落ちる / `0xC0000005` になる | Node.js を 22.21.0 以降（または 24 系）に更新する。または `C:\work\chatroom` のような ASCII のみのパスへ移動する。 |
| スマートフォンから `localhost` に繋がらない | `npx wrangler dev --ip 0.0.0.0` で起動し、Windows ファイアウォールで Node.js の受信を許可する。スマートフォンでは PC の LAN IP（`http://192.168.x.x:8787`）を開く。 |
| 通知が出ない | 通知を許可する。HTTPS または `localhost` で開く。ページを開いたままバックグラウンドにしているか確認する。iOS は iOS 16.4 以降 + ホーム画面追加が必要。仕様上、ページを完全に閉じると届かない。 |
| 画像が送れない | 元ファイルが 25MB 以下か確認する。圧縮後の data URL が 240,000 文字を超える場合は送信できないため、別の画像を選ぶ。 |
| ホスト操作ができない | ホスト権限は `localStorage` の `hostId` に依存する。ブラウザデータを消した場合や別のブラウザでは復元できない。 |
